# 从资损案例看交易所防御

[仓库首页](../../README.zh-CN.md) · [English](../en/defense-matrix.md) | **简体中文**

[调查正文](research.md) · [六类攻击路径](attack-paths.md) · **防御矩阵** · [案例目录](case-catalogue.md) · [统计方法](methodology.md)

本矩阵以近十年加密交易所公开披露的真实资损安全事件为主要依据，从攻击者取得权限、绕过防御到转走资产的过程，推导交易所的防御建设与验收要求，并结合成功阻断及相关技术案例补充验证场景。六条攻击路径对应18项建设工作，逐项列出业务团队与安全团队的责任、协作方式和验收证据。建设项按业务风险和控制对象组织；应用安全、GRC、红队等专业职能参与相应工作，代码审计列入应用安全。案例与归因见[交易所安全案例目录](case-catalogue.md)，技术路径见[交易所六类攻击路径解读](attack-paths.md)。

## 一、攻击路径与检查缺口

| 攻击路径及历史依据 | 攻击者取得的能力 | 常见检查 | 仍需核查的风险 | 对应建设项 |
| --- | --- | --- | --- | --- |
| P1 签名材料泄露：Coincheck、BitMart、Zilliqa | 取得足够签名材料，或利用实现缺陷恢复私钥 | 本方签名调用的权限及日志 | 备份、恢复和历史签名中的泄露；攻击者在外部继续签名 | D04、D06、D11、D15 |
| P2 交易内容篡改：Bybit、Kiln；DMM为可能链路 | 修改交易构造、展示或请求内容 | 签名有效性、批准人数 | 获批内容偏离原始业务请求；多名批准者共用被篡改的展示 | D07、D12、D16 |
| P3 账户与提现授权接管：Coinbase恢复、WOO X；Parity为外部对照 | 改写身份资料、伪造内部指令或绕过合约权限检查 | 当前身份的认证与授权 | 恢复流程、后台写权限和合约初始化可改变谁有权转账 | D02、D05、D06、D08、D10、D12 |
| P4 交易与估值操纵：Binance VIA；Mango为外部对照 | 盗用交易权，或使用自有账户操纵薄流动性市场 | API下单权限、账本加减 | 异常成交转移客户权益；虚高估值扩大可借额度 | D10、D13、D14 |
| P5 错误入账与双花：Kraken、ETC | 利用入账缺陷或链重组形成可用余额 | 内部账务一致性、提现授权 | 充值未完成或被撤销；错误余额已用于换币、借贷和提现 | D09、D10、D13 |
| P6 诱骗客户转账或授权：Coinbase支持人员事件 | 利用客户资料冒充可信身份，诱导本人操作 | 本人登录和操作确认 | 客户误信收款方及转账理由；支持人员持续泄露资料 | D08、D14、D16 |
| 恢复与退役：ShapeShift、CoinDCX、Zilliqa | 沿旧入口取得新凭据，继续使用旧权限，或控制旧地址新增余额 | 服务可用性、已知漏洞修补 | 旧会话、公开签名、恢复环境和后续收款仍可被利用 | D11、D15、D17 |

Coinbase 2023的MFA阻断了直接登录，后续社工还需要人员响应；Binance VIA的外提被拦，但部分受害成交无法撤回。验证结果分别记录入侵是否继续、资金是否转出，以及客户权益是否已经受损。

## 二、资金业务与责任分工

每条资金路径先记录以下内容。仅对本方已开展的业务填写；未开展的质押、借贷等标为不适用。

| 对象 | 最少记录内容 | 完整性检查 |
| --- | --- | --- |
| 资产与客户权益 | 资产、链、钱包／托管方、账户权益来源、解锁或赎回条件 | 将地址和链资产、内部账务、外部托管记录对应起来；未对账项单列 |
| 业务动作及状态 | 充值、交易、提现、补充资金、权限变更；维护、恢复、退役状态 | 覆盖正常流程及例外流程，保留业务请求到链上结果的对应关系 |
| 人员与服务身份 | 人员、角色、设备、会话、服务账号、令牌的用途及负责人 | 检查谁能操作，谁能改变校验依据，谁能恢复或重新签发权限 |
| 控制与依赖 | 独立限制、第三方输入、日志、撤权方法、恢复条件 | 记录同一身份可以修改的多项控制；记录无法获取的日志和不可即时撤销的权限 |
| 影响与责任 | 直接资产、可调拨资产、后续流入；业务负责人、控制维护人、应急执行人 | 资产去重；标明评估时限与假设；没有验证的限制不能作为损失上限依据 |

业务和技术团队负责本方系统的控制实现与持续运行，安全团队参与风险分析、提出安全要求并组织验证。下表列出协作主体及角色，安全团队的专业职能在2.1中展开。职能可以兼岗，每项工作仍需明确负责人和替补。资金操作、策略变更和有效性复核分别授权；同一人或服务身份能否绕过这些安排，纳入验证。

| 协作主体／角色 | 负责的结果 | 与其他参与方的交接 |
| --- | --- | --- |
| 管理层与业务负责人 | 确定资金使用需求、建设资源、停限业务权限及未解决风险的处置 | 批准临时限制和恢复的范围；确认流动性、持仓及客户影响 |
| 安全团队，由CSO或指定负责人统筹 | 组织风险分析、设计评审、检测响应及独立技术验证，跟踪未解决风险 | 按风险安排专业职能参与；与系统负责人确定控制维护人、修复责任人和验收人，向业务负责人报告剩余风险 |
| 产品、账户及账务研发 | 维护认证恢复、业务授权、入账和权益流转规则 | 将设计、代码变更及例外路径交相关安全职能评审；向风控、钱包和安全运营提供请求标识与状态变化 |
| 提现风控与出金编排 | 风控确定限制对象及操作；编排维护业务单、签名请求、批次与链上结果的映射 | 将限制落实到合批、拆单与重试任务，按业务单汇总执行状态；不把客户识别职责直接交给签名服务 |
| 钱包团队 | 维护签名系统、交易解析、广播和链上权限检查 | 接收业务批准依据；回报交易状态、残留签名及链上权限，执行获批迁移 |
| 资金运营 | 管理余额、补款、调拨和外部托管资产 | 提供流动性需求及可用资金；与钱包、账务核对在途资产，执行补款限制 |
| 交易及信用风险职能 | 管理异常成交、定价、可借额度、集中度和清算风险 | 与账户、账务和安全共享账户关系及资金用途，限制跨业务兑出 |
| IT、身份平台和SRE | 管理终端、会话、云权限、发布、运行环境与恢复基础设施 | 提供实际撤权和隔离结果，不以个人账号停用代替所有派生权限失效 |
| 事件指挥 | 协调跨部门处置，决定授权范围内的升级和临时限制 | 处理超时、部分失败和业务冲突；恢复审批交指定业务授权人，保留决定依据 |
| 人力与系统负责人 | 同步岗位变化、离职及维护责任交接 | 向IT和身份平台提供撤权对象；由技术执行方回报会话与关联凭据处理结果 |
| 客服与反欺诈 | 接收客户报案、核验身份及异常资金行为 | 向安全运营提供查询记录和受影响账户；恢复账户与解除资金限制分别授权 |
| 供应商管理、采购与法务 | 约定外部访问、事件通知、日志支持及退出安排 | 与使用服务的系统负责人核对实际权限、应急联系人及撤销结果 |

### 2.1 安全团队的专业职能

以下按承担的工作划分职能，不要求分别设置部门。一个风险可以涉及多项职能；应用安全中的代码审计、红队开展的攻击模拟，属于具体工作。GRC指治理、风险与合规。

| 专业职能 | 主要参与项 | 工作与验收职责 |
| --- | --- | --- |
| 安全架构 | D01、D02、D06、D10—D12、D15、D18 | 分析信任关系和共同管理权限，与研发、钱包及平台团队确定控制边界；检查单一身份能否同时改写请求、批准依据和验证记录 |
| 应用安全 | D05、D07—D10、D12、D13、D16、D18 | 参与需求与设计评审、威胁建模、代码审计、依赖检查及业务逻辑测试；与研发核对修复版本，保留缺陷复现、修复后拒绝结果和同类代码排查记录 |
| 基础设施与身份安全 | D02—D07、D15—D18 | 与IT、身份平台及SRE核查终端、网络、云和生产访问；验证隔离、撤权和恢复后仍有效的会话与派生权限 |
| 钱包与合约安全 | D09—D12、D15、D16 | 与钱包、链接入及资金团队检查签名实现、交易解析、合约权限和密钥恢复；以实际字节、执行结果及链上权限验证资产控制范围 |
| 数据安全 | D02、D04、D06、D08、D16—D18 | 与数据和系统负责人检查敏感信息访问、导出、日志及第三方使用；验证批量与低频持续查询、撤权后访问和Agent工具返回是否泄露数据 |
| 安全运营 | D03—D06、D08、D13—D18 | 关联技术与业务信号，开展狩猎、调查和响应；与执行团队核实限制对象及生效结果，记录漏检、误报、处置失败和响应时间 |
| GRC | D01—D18的风险、例外与控制检查 | 将适用要求对应到控制及负责人；抽查实际执行记录，跟踪未验证项、风险例外和到期复核，与采购法务核查供应商承诺；风险接受交有权的业务负责人批准 |
| 红队 | 按风险选取D02—D18的组合场景，依据D01确定资产影响 | 在授权范围内探索跨系统攻击路径，重放历史手法，检验防护和响应；保留起始权限、利用过程、实际业务结果及未覆盖范围，复核修复能否被绕过 |

应用安全与钱包安全按代码组件和风险分工，例如由应用安全审查提现服务的业务授权，由钱包安全审查签名及链上权限；共同影响的路径联合验证。红队保留独立攻击假设和取证渠道。管理制度及合规执行的独立审计由相应审计职能承担，不列入红队技术验证或GRC日常自查。

### 2.2 设计、开发与风险例外的交接

新业务、关键代码或权限变更，由系统负责人提交业务流程、变更范围和依赖。安全架构及相关专业职能确定风险与测试要求，研发实施修复并提供版本和测试结果；应用安全复核实现，高风险跨系统路径再安排红队或其他独立技术人员验证。运行中的监测和处置交安全运营维护，所需日志及执行接口由系统团队提供。

无法按期完成的控制，由GRC记录受影响业务、剩余风险、临时措施、负责人和期限，交有权的业务负责人决定接受、限制或延期。例外获批后仍保留原验证结果；到期或业务条件变化时重新评估。控制检查抽取实际授权、变更和处置记录，并结合技术测试，不能仅凭制度文档、访谈或认证证书判定有效。

### 2.3 事件触发与部门交接

会话盗用、未授权生产写入或交易内容不符，触发对应对象的预授权处置。待核实信号达到预设的高风险条件时，可先限制特定账户、请求或业务，再并行核查。临时限制写明范围、复核期限和解除权限；到期仍未查清则升级，不自动放行。已确认失陷的设备和会话先隔离，业务映射继续补齐。

交接内容包括事件与动作标识、证据来源、时间精度、对象、限制版本、执行期限和责任人。凭据只传标识。回执分别记录接收、执行、验证生效的时刻，并列失败和未知项；生效时刻不明时，记录最后一次成功操作至首次验证拒绝的区间。失败立即升级，超时交当班事件指挥及替补。已跨过最后可阻断节点的任务转入残留签名、链上权限和资产处置，继续限制后续任务。

| 交接 | 触发与传递内容 | 接收方动作及回执 |
| --- | --- | --- |
| 安全运营 → 身份／平台、风控 | 已确认失陷，或达到预设高风险条件；传递身份、会话、证据、已知服务及映射缺口 | 按授权范围并行隔离访问和限制业务；追查派生凭据及重新签发路径。待核实限制按期限复核，未知范围继续调查 |
| 平台／研发 → 风控、账户及账务 | 发现实际写入、发布变化或残余权限；变更对象、服务身份、时间段及未明范围 | 将可访问范围与确认受影响对象分开；关联客户及业务单，调整限制，未明范围交事件指挥决定临时处置 |
| 风控 → 出金编排 → 钱包 | 关联出金受限；业务单、操作类型、限制版本及范围；编排补齐签名请求、合批／拆单关系、链及钱包 | 阻断受影响任务的签名、广播和重试。合批无法安全拆分时先保持该批受限；重建交易须重新校验与授权，已签内容另查外部执行能力 |
| 钱包 → 编排 → 风控 | 按签名请求返回未签、已签未播、已广播待确认、链上确认状态；携带实际限制版本、证据和残余能力 | 编排映射回业务单，标明部分失败、未知项及可能同批受影响业务。确认状态随链更新；删除队列不计作签名失效。失败、超时或仍可外部执行立即升级 |
| 风控／客服 → 安全运营 | 异常恢复、关联资金行为或客户受骗报案；账户、订单、访问记录和时间范围 | 关联后台写入、部署、员工查询及会话；回复是否发现入侵证据；反欺诈处置不等待组织归因 |
| 各执行方 → 业务／事件指挥 | 拟恢复范围的执行证据、安全复核、可用资金及账务差异；另列仍隔离业务和未解决项 | 批准具体范围、限额、观察条件与再次暂停信号；指定执行及替补负责人。未验证控制和未解释差异不能记为通过；追赃进度与技术恢复分别记录 |

执行方校验指令来源、权限和版本，防止重复资产操作及旧指令覆盖新限制。解除限制单独授权。验证读取目标状态，并以受控请求确认操作已被拒绝；保留实际生效实例、故障实例、失联实例及已签或已广播任务的结果。控制面受侵时，使用预先验证的独立应急访问；核验记录保存在受影响身份无法改写的位置。

## 三、建设项与验收证据

验证记录绑定环境、版本和业务范围。涉及生产、客户资产或供应商的测试，先确定授权、规模和中止条件；只在测试环境完成的项目，注明生产尚未验证。

各建设项由牵头方落实控制，列出的安全职能承担相应评审与验证。GRC按风险安排控制检查和例外跟踪，红队按授权范围选择组合路径，不要求两者参与每一次常规变更。每项验收分别记录实现负责人、专业复核人和结论；高风险控制另行安排独立技术验证。接受剩余风险不会将“验证失败”或“未验证”改记为通过。

### 3.1 业务、人员与基础设施

| 编号／对象 | 具体工作 | 牵头与协作 | 验收证据 |
| --- | --- | --- | --- |
| D01 资金业务范围 | 对应资产、客户余额、业务状态及修改权限，覆盖调拨、维护、恢复和退役 | 业务负责人牵头；资金、账务、钱包、安全架构和GRC配合 | 抽取业务请求能追到记账与资金结果；未对账项、无人负责系统和未测试路径单列 |
| D02 人员与服务身份 | 登记账户、发布、资金规则、密钥及日志的修改权限；为服务身份指定用途、期限和负责人 | 身份管理负责人牵头；HR、IT、系统负责人及基础设施与身份安全配合 | 从选定高权限人员追查个人会话及关联服务身份；记录不明用途账号及其保留、撤销结果 |

## 四、联合验证场景

每次验证记录业务范围、环境与版本、起始权限、预期阻断位置和实际结果。时间线区分首次可检测行为、发现、限制生效、根除和恢复；同时记录资产及账务变化、未覆盖项、执行人与复核人。无法确认的时间标为“未知”，注明原因。

红队或独立技术复核人员组织跨系统攻击验证，应用、基础设施、数据及钱包安全按涉及组件参与分析，业务和技术团队提供真实状态与修复结果。安全运营检查信号是否产生、调查是否关联到正确业务、处置是否生效；GRC核对失败及未覆盖项是否进入风险跟踪。一个场景没有成功利用，只能说明本次条件下的结果，仍需保留测试范围和限制。

| 验证场景 | 联动建设项 | 检查重点 |
| --- | --- | --- |
| 开发者终端受控后，尝试沿已有会话接近生产 | D02、D04—D07、D14 | 终端隔离之外，已有云会话和派生服务凭据是否仍可用；发布和生产数据库能否继续被修改 |
| 第三方返回针对某钱包的异常交易 | D07、D12、D16 | 使用对应钱包、金额及权限状态；核对最终字节与原始业务请求，分别记录签名前、广播前及链上执行后的检查结果 |
| 授权被外部提交、执行失败或委托随后清除 | D10—D12、D14、D15 | 覆盖各签名入口；EIP-7702执行失败仍可留下已处理成功的委托，清除委托也不撤销代币授权；chain_id为0的授权在其他支持链上满足nonce等条件时仍可能生效，按链复测 |
| 支持身份访问客户信息并发起恢复流程 | D05、D08、D10、D14 | 分开测试员工身份恢复与客户账户恢复；资料查询不能自动获得解除出金限制的能力 |
| 错误充值／估值经现货、抵押或借贷转到另一资产 | D09、D10、D13 | 追踪可用权益来源及用途；不只在最初币种或最初钱包上停提 |
| 安全异常和风控异常分别成为事件起点 | D08、D10、D13、D14 | 测试已确认失陷与达到预设条件的待核实信号；验证临时限制、复核、误报解除及升级。异常资金行为能够触发后台写入和部署排查 |
| 风控、定价或链节点依赖故障 | D09、D10、D13、D14 | 验证超时、过期输入及节点分歧下的业务限制；确认存量持仓、客户申诉及积压交易如何继续处理 |
| 并发放行、交易变更，或停提时仍有合批及重试任务 | D10、D12、D14 | 测试多个实例或链任务争用共享额度：累计占用不超限，同一业务不重复扣占，结果未明的交易不提前释放额度；业务单与签名请求双向追溯，拆单／合批保留限制，旧放行不能授权新内容；重试先核对已有交易结果 |
| 交接丢失、乱序、对象错配或部分执行失败 | D10、D14、D15 | 旧指令不能覆盖新限制，重复指令不重复执行资产动作；成功接口回执与实际拒绝行为分开；按期限升级到当班及替补负责人 |
| 响应后用旧访问及旧地址继续尝试 | D11、D14—D17 | 检查旧会话、派生凭据、已签交易、链上授权、恢复环境及未来收款；未知区域继续隔离，拟恢复范围单独验证；监测中断可重新限制 |

各场景分别保留成功与失败记录。不适用项注明对应业务尚未开展或已退役；缺乏日志、授权或安全测试条件的项目记为未验证。

## 五、建设顺序与效果评价

已泄露凭据、正在被利用的漏洞和已确认的未授权访问先处置。D01—D06核对资金、身份、入口和生产访问，D14同步落实检测、限制及值班交接。同一身份能修改资金请求和校验规则时，优先拆分权限；已有独立拦截的路径，继续检查发现延迟、仍可转出的资产及恢复缺口。

D07—D13按本方业务并行建设。降低在线余额会增加调拨，交易解析覆盖不足会限制新业务接入，账户复核会延长客户恢复，限开仓、限借款和停清算会产生不同的持仓风险。业务负责人和控制维护人共同确定范围及资源，保留改造前后的验证结果。客户恢复与受骗主动操作分别测试；已转至平台外自托管的资产，记录本方仍可采取的具体动作。

D15—D18处理恢复、供应商、人员和自动化变化。新链、新业务、重要权限及供应商接入后，更新受影响路径并复测。建设与复核分别安排负责人，未解决项注明期限和业务处置决定。

安全团队使用Agent时，各专业职能继续负责本领域的工作质量。应用安全维护设计、代码审计与修复验证用例，安全运营维护调查和响应任务，GRC核对控制证据与例外状态，红队探索绕过路径。调查中的发现可以转为研发任务，修复版本和复测结果关联回原事件。实时引擎承接事件与定时任务，专家工作台用于追问证据、补充上下文，有权人员审批超出预授权的动作。工具访问、累计影响及预授权限制由模型外的执行层约束，结果从身份、账务、链节点等系统核验。案件、证据、策略、Skill及评估集保留在企业控制的存储中。

钱包、身份恢复和出金编排变更后，重跑相关攻击用例，记录变更到复测的间隔。红队另行探索已有用例之外的路径，保留独立测试假设和取证；模型、上下文或规则相同的多个Agent不直接计作独立验证。测试范围包括安全策略、长期记忆和评估数据被篡改，以及恶意工单或代码内容诱导越权。

扩展执行权限前，先回放历史事件并运行影子任务，比较错误放行、误限制、人工接管和重复失败；执行开放后继续记录发现、限制生效、修复及复测时间。评估答案由真实结果与专业复核确定，不能直接沿用Agent自评；保留人工抽样和接管演练。误判修正进入Skill、策略或评估用例，记录维护人、版本及适用范围，模型更换后重新验证。紧急阻断继续遵循现有预授权策略。攻击侧依据见[调查正文](research.md)。

| 检测与遏制 | TTD从明确失陷到发现，TTC从发现到约定限制验证生效 | 初始失陷未知时单列已知行为至发现的间隔；保留未完成处置，遏制与根除分开 |
| 恢复及残留风险 | 分服务记录恢复时刻、旧访问复测、后续资金流及未解决项 | 恢复计划与实际恢复分别记录；赔付和资产补充不计作技术恢复 |
| 可被转出的资产 | 在明确时限和假设下，记录去重资产、后续流入及阻断前结果 | 只计入已验证限制的效果；已受损权益、可达资产和实际资损分别记录 |
